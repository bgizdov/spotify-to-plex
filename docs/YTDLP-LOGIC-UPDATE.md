# YT-DLP Logic Update

## Summary

Updated YT-DLP sync logic to match SLSKD behavior, ensuring consistent file generation and proper separation of concerns between sync types.

## Changes Made

### 1. File Generation Sources

**Before:**
- `missing_tracks_slskd.json` was generated by playlists/albums sync
- `missing_tracks_ytdlp.json` was generated by ytdlp.ts AFTER processing
- YT-DLP read from `missing_tracks_slskd.json` and filtered based on SLSKD results

**After:**
- `missing_tracks_slskd.json` is generated by playlists/albums sync (unchanged)
- `missing_tracks_ytdlp.json` is now ALSO generated by playlists/albums sync
- YT-DLP now reads from `missing_tracks_ytdlp.json`
- Both files contain the same data: **all tracks missing from Plex**

### 2. Fallback Mode Behavior

**When `fallback_only = false` (default):**
- `missing_tracks_ytdlp.json` contains ALL tracks missing from Plex
- YT-DLP processes all tracks in the file
- Independent of SLSKD results

**When `fallback_only = true`:**
- Playlists/Albums sync reads `slskd_sync_log.json` during file generation
- `missing_tracks_ytdlp.json` contains ONLY tracks with `status: "not_found"` from SLSKD
- YT-DLP processes all tracks in the file (already filtered)
- No runtime filtering needed

**Key Change:** Filtering now happens at file generation time, not at YT-DLP runtime.

### 3. Log Structure

Both SLSKD and YT-DLP now have consistent log structures:

**`slskd_sync_log.json`:**
```json
{
  "timestamp-trackkey": {
    "id": "timestamp-trackkey",
    "artist_name": "Artist Name",
    "track_name": "Track Name",
    "status": "queued" | "not_found" | "error",
    "start": 1234567890,
    "end": 1234567890,
    "file_path": "/path/to/file.mp3",  // if queued
    "error": "Error message"  // if error/not_found
  }
}
```

**`ytdlp_sync_log.json`:**
```json
{
  "timestamp-trackkey": {
    "id": "timestamp-trackkey",
    "artist_name": "Artist Name",
    "track_name": "Track Name",
    "status": "completed" | "error",
    "start": 1234567890,
    "end": 1234567890,
    "video_url": "https://youtube.com/...",  // if completed
    "video_title": "Video Title",  // if completed
    "file_path": "/path/to/file.mp3",  // if completed
    "error": "Error message"  // if error
  }
}
```

## Benefits

1. **Consistency**: Both SLSKD and YT-DLP follow the same pattern
2. **Clarity**: File names clearly indicate their purpose (input to each sync type)
3. **Flexibility**: Fallback mode still works by checking SLSKD logs
4. **Independence**: YT-DLP can run independently without SLSKD data (when fallback_only = false)

## Files Changed

1. **`apps/sync-worker/src/jobs/playlists.ts`**
   - Added generation of `missing_tracks_ytdlp.json`

2. **`apps/sync-worker/src/jobs/albums.ts`**
   - Added generation of `missing_tracks_ytdlp.json`

3. **`apps/sync-worker/src/jobs/ytdlp.ts`**
   - Changed to read from `missing_tracks_ytdlp.json` instead of `missing_tracks_slskd.json`
   - Removed duplicate generation of `missing_tracks_ytdlp.json` at the end
   - Fallback mode logic remains unchanged (still checks `slskd_sync_log.json`)

## Migration Notes

For existing installations:
- After updating, run a full playlist/album sync to generate both files
- Old `missing_tracks_ytdlp.json` files will be overwritten with the new format
- No data loss occurs - both files contain the same source data (tracks missing from Plex)

## Testing

To verify the changes:

1. **Run playlist sync:**
   ```bash
   npm run sync:playlists
   ```
   - Verify both `missing_tracks_slskd.json` and `missing_tracks_ytdlp.json` are created
   - Verify they contain the same tracks

2. **Run SLSKD sync:**
   ```bash
   npm run sync:slskd
   ```
   - Verify `slskd_sync_log.json` is updated with results

3. **Run YT-DLP sync (fallback mode):**
   ```bash
   npm run sync:ytdlp
   ```
   - With `fallback_only = true`, verify it only processes tracks with `status: "not_found"` from SLSKD
   - With `fallback_only = false`, verify it processes all tracks

## Important: Fallback Mode File Filtering

When `fallback_only = true`, the filtering now happens at **file generation time** in playlists.ts/albums.ts, not at runtime in ytdlp.ts. This means:

1. Playlists/Albums sync checks the YT-DLP `fallback_only` setting
2. If enabled, it reads `slskd_sync_log.json` and filters tracks
3. Only tracks with `status: "not_found"` are written to `missing_tracks_ytdlp.json`
4. YT-DLP simply processes all tracks in the file (no filtering needed)

**Recommended workflow for fallback mode:**
```bash
npm run sync:playlists  # Generate initial missing tracks
npm run sync:slskd      # Download via P2P, create log
npm run sync:playlists  # Regenerate ytdlp file (now filtered)
npm run sync:ytdlp      # Download only what SLSKD couldn't find
```

See `FALLBACK-MODE-FILE-FILTERING.md` for detailed explanation.
